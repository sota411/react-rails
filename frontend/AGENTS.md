# Codex向け: Reactを教えるときの追加ルール

このディレクトリでは、学習者はReactを初めて触ります。ルートの `AGENTS.md` に加えて次を守ってください。

## 説明する順番

1. 完成画面のどこが変わるか指す
2. イベントの入口を探す。例: `onClick`, `onSubmit`
3. そのイベントが呼ぶ関数を探す
4. `state（画面が覚える値）` の変更を探す
5. JSXのどこが再表示されるか探す

## 初出語の言い換え

- Component: 画面の部品
- props: 親の部品から渡される値
- state: 画面が覚えておく値
- render / 再レンダー: stateをもとに画面を描き直すこと
- event: クリックや入力など、ユーザー操作の知らせ
- hook: Reactの機能を関数部品から使う仕組み

## コード編集時

- `App.jsx` を巨大化させず、今ある部品の責任を保つ
- 初学者が追えない1行の技巧より、3行の明示的な処理を選ぶ
- 三項演算子の入れ子、短絡評価の連続、過剰な分割代入を避ける
- `useEffect` を追加するときは「何をきっかけに、何を同期するか」を先に説明する
- 配列を直接 `push` で変更せず、新しい配列を作る理由を説明する
- API通信は `src/api/tasks.js` に置き、画面部品へ `fetch` を散らさない

1. ブラウザの画面
2. DevToolsのConsole
3. DevToolsのNetwork
4. `npm test`

「動いた」だけで終わらず、どのstateがどう変わったかを質問してください。
